# Development

Everything runs from the locked Nix dev shell; nothing is installed or
activated.

```sh
nix develop
sd areel build          # ./areel
sd areel check          # gofmt, go test, go vet, help, plugin tests: run before every change
sd areel run help       # build ./areel and run it with arguments
```

Use `sd areel run …` (or `./areel`), not `go run`, to try recordings: the
detached holder re-executes its own binary, and `go run` deletes it on exit.

## Test suites

| Task | Covers | Needs |
|---|---|---|
| `test` | fast Go unit and fake-backend contracts | |
| `check` | `test` plus vet, gofmt, help, asset pins and OpenCode shim tests | |
| `ui-check` | HTML, marks and activity contracts, shipped asset hashes | |
| `race-check` | the Go race detector | |
| `checkpoint-check` | the pinned `avt` helper against the player | `nix develop` |
| `browser-check` | real Chromium: library, history, search, exports, web embeds | `nix develop` |
| `zellij-check` | real Zellij and asciinema in throwaway sessions | Zellij on PATH |
| `video-check` | H.264/ProRes renders, decoded-pixel checks | `nix develop` |
| `video-race-check` | `video-check` under the race detector | `nix develop` |
| `pi-check` | Pi extension typecheck and tests | npm |
| `plugin-check` | OpenCode shim tests | bun |
| `nix-check` | the Nix package and its contract | Nix |
| `docs-assets` | rebuild `docs/images/` and `docs/demo/` from the demo recordings | `nix develop` |
| `qualify-smoke` / `qualify` | the long capture qualification (full profile: ~8 h, 40 GiB) | idle machine |

Browser and video suites use synthetic private libraries and never touch
your real one. `AREEL_BROWSER_EVIDENCE=DIR` and `AREEL_VIDEO_EVIDENCE=DIR`
keep their screenshots and artifacts.

## Pinned pieces

`flake.lock` pins the dev shell's Go, Chromium, asciinema 3.2.1, Zellij and
FFmpeg. Capture uses whichever Zellij is on PATH; 0.44.3 and 0.45.1 are
validated, and `areel doctor` warns about others.

- **`tools/avt-checkpoint`**: a tiny Rust helper wrapping
  [avt](https://github.com/asciinema/avt) 0.18.0, the terminal emulator
  asciinema uses. It turns recorder output into screens. All application
  logic is Go.
- **asciinema-player 3.17.0**: vendored unmodified. `package.json` pins
  the version and `scripts/assets.mjs` the hashes; `sd areel assets-build`
  recopies it.
- **Fonts**: DejaVu Sans Mono, plus AgentReelBox, a box-drawing subset
  generated by `scripts/box-font.py` so pane borders join up.
- **Go dependencies**: `creack/pty`, `klauspost/compress` and, for browser
  tests, `chromedp`.

## Layout

| Path | |
|---|---|
| `cmd/areel` | the CLI entrypoint |
| `internal/reel` | commands, holder, library server and web UI (`internal/reel/web`) |
| `internal/visualcapture`, `visualstore`, `seal` | capture into screens, the store, the sealed `.areel` format |
| `internal/castexport`, `videoexport`, `webembed`, `editmap` | exports, video rendering, web embeds, recipes and EDLs |
| `internal/textindex` | search index |
| `agent-plugin/` | Claude Code, Codex and OpenCode hooks |
| `pi/` | the Pi extension |
| `nix/` | package, Home Manager module, checks |
| `tools/demo-record` | scripted demo recordings (the README footage) |

Domain vocabulary and product decisions live in [CONTEXT.md](../CONTEXT.md).

## Docs images

The README footage and screenshots come from real, scripted agent sessions.
`tools/demo-record/record.py --agent claude|codex|pi` records them; then
`sd areel docs-assets` rebuilds `docs/images/` and `docs/demo/` from them.
See [`tools/demo-record`](../tools/demo-record/README.md).
